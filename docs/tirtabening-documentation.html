Alur Bisnis

Alur utama dari master data sampai pembayaran dan laporan.

Setup Sistem

Admin mengisi setting tarif per m3, abonemen, biaya admin, tanggal jatuh tempo, denda, profil perusahaan, rekening pembayaran, bendahara, dan WhatsApp CS.

Master Distribusi

Admin membuat tandon, zona/blok, petugas, dan menghubungkan pelanggan ke zona serta user warga.

Periode Catat Meter

Admin/petugas membuat periode YYYY-MM. Sistem snapshot tarif dan abonemen dari setting, lalu generate baris CatatMeter untuk pelanggan aktif.

Pencatatan Meter

Petugas mengisi meter akhir. Sistem menghitung pemakaian, total, status DONE, dan memperbarui progress periode serta jadwal zona.

Finalisasi dan Tagihan

Baris catat meter yang selesai dapat dikunci/finalisasi. Endpoint finalisasi membuat atau memperbarui tagihan, mengunci baris, dan menjadikan periode FINAL bila semua baris terkunci.

Kirim Tagihan WA

Sistem membuat pesan ringkasan tagihan, gambar tagihan, magic link warga, lalu mengirim ke nomor wa dan wa2 lewat WA Sender.

Pembayaran dan Pelunasan

Pembayaran dibuat dari form pelunasan/input pembayaran. Bukti transfer dikompresi, detail pembayaran dialokasikan ke tagihan lama sampai baru, lalu sistem menghitung sisa kurang atau kredit.

Revisi Pembayaran

Admin/petugas dapat merevisi pembayaran. Sistem menghapus ulang detail alokasi lama untuk pembayaran tersebut, membangun alokasi baru, dan menghitung ulang status serta carry-over.

Laporan

Dashboard dan laporan membaca data tagihan, pembayaran, catat meter, pengeluaran, pemasukan, hutang, pajak, serta distribusi untuk kebutuhan monitoring operasional dan keuangan.

Rumus catat meter: pemakaian = max(meterAkhir - meterAwal, 0) dan total = tarifPerM3 * pemakaian + abonemen. Pada finalisasi tagihan, total juga memperhitungkan biayaAdmin dari setting.
Alur pembayaran memakai DetailPembayaran sebagai sumber alokasi. Field sisaKurang dan tagihanLalu berperan sebagai snapshot carry-over antar periode.

Security

Catatan keamanan berdasarkan implementasi saat ini.

Auth Saat Ini

  • Middleware menjaga beberapa halaman protected memakai cookie tb_token.
  • Magic link memakai tabel MagicLinkToken dan session cookie session.
  • Beberapa route juga membaca fallback cookie/header via getAuthUserId.

Rekomendasi Production

  • Standarkan auth API pada satu guard server-side untuk semua route sensitif.
  • Hindari mempercayai header x-user-id/x-user-role dari client tanpa token tervalidasi.
  • Rotasi JWT_SECRET dan WA_SENDER_API_KEY dengan secret manager.
  • Pastikan cookie production memakai httpOnly, secure, dan sameSite.
Field Pelanggan.passwordPlain ada di schema. Untuk production, hindari penyimpanan password plaintext. Bila masih dibutuhkan untuk migrasi/operasional, batasi akses, audit penggunaan, dan rencanakan penghapusan field tersebut.

Rekomendasi Production-Grade

Prioritas perbaikan agar scalable, maintainable, dan aman.

1. Konsolidasi API Guard

Buat helper auth/role tunggal untuk route API. Semua endpoint mutasi harus memvalidasi user dari token/session, bukan header client mentah.

2. Service Layer

Pindahkan alur bisnis berat seperti finalisasi tagihan, pelunasan, dan revisi pembayaran ke service module terpisah agar bisa diuji unit/integration.

3. Testing

Tambahkan test untuk payment allocation, carry-over, finalisasi periode, reset meter, dan WA log failure handling.

4. Observability

Tambahkan structured logging, request id, error boundary API, dan alert untuk WA Sender disconnected atau job pengiriman gagal.

5. Data Retention

Definisikan kebijakan backup database, backup upload, arsip PDF/gambar, dan pembersihan log WhatsApp.

6. Dokumentasi Lanjutan

Tambahkan OpenAPI/Swagger atau contract test dari route API agar endpoint selalu sinkron dengan implementasi.
